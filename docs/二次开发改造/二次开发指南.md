# 二次开发指南

这份指南只讲最终做法。

## 1. 改哪里

不要去平台层到处改交易规则。

固定策略入口是：

- `src/polymarket_trader/strategies/current/strategy.py`
- `src/polymarket_trader/strategies/current/config.py`
- `src/polymarket_trader/strategies/current/market_filter.py`
- `src/polymarket_trader/strategies/current/trading_strategy.py`
- `src/polymarket_trader/strategies/current/subscription.py`

这里就是当前策略实现，也是二次开发的直接起点。业务改造优先只在这几个文件里完成。

## 2. 推荐开始方式

1. 先看 `current/strategy.py`，理解当前入口如何装配业务模块
2. 在 `current/market_filter.py` 里声明远端市场发现条件和最终筛选逻辑
3. 在 `current/trading_strategy.py` 里写分配、入场、退出、恢复逻辑
4. 在 `current/subscription.py` 里写“禁止新开仓但保留订阅”的规则
5. 把交易阈值常量写进 `current/config.py`

单策略项目里，`current/` 就是实际运行入口。

发现查询接口官方文档：

- Events: <https://docs.polymarket.com/api-reference/events/list-events>
- Events Keyset: <https://docs.polymarket.com/api-reference/events/list-events-keyset-pagination>
- Markets: <https://docs.polymarket.com/api-reference/markets/list-markets>
- Markets Keyset: <https://docs.polymarket.com/api-reference/markets/list-markets-keyset-pagination>

建议：

- 官方接口已经支持的过滤条件，直接写进 `params`
- `params` 保持官方字段原样，不额外包一层自定义结构
- `select_market()` 继续保留最终准入判断，不把交易语义硬塞给框架层

WebSocket 这一层要单独理解：

- `build_discovery_queries()` 只管 Gamma 发现参数
- `select_market()` 只管最终准入
- 进入 registry 的 market，才会由框架自动生成 WS 订阅
- 当前不是“策略直接传 WebSocket 订阅 payload”的设计

当前框架约定：

- Market Channel：按 `NO token_id` 订阅
- User Channel：按 `condition_id` 订阅
- Market Channel 固定开启 `custom_feature_enabled: true`

官方 WebSocket 文档：

- Overview: <https://docs.polymarket.com/market-data/websocket/overview>
- Market Channel: <https://docs.polymarket.com/market-data/websocket/market-channel>

官方当前不能通过订阅参数按消息类型精细开关，只能：

- 选择订阅哪些 `assets_ids`
- 选择是否开启 `custom_feature_enabled`

## 3. 不要改的地方

二次开发时，下面这些默认不要改：

- `runtime/`
- `workers/`
- `infra/polymarket/`
- `app/trading_service.py`
- 风控和执行链路

只有当你的策略能力明确要求平台新增通用能力时，才去改平台层。

## 4. 本地验证顺序

先跑契约测试：

```bash
pytest tests/strategies/contract
```

再跑 replay：

```python
from polymarket_trader.strategy_api.replay import run_entry_replay

payload = run_entry_replay("tests/strategies/fixtures/entry_replay.json")
print(payload["plan"]["ready_to_trade"])
```

如果 replay 没输出 `ready_to_trade=true`，先修策略，不要急着起整套 runtime。

最后再跑全量测试：

```bash
pytest
```

## 5. 配置建议

当前内置策略不再使用额外的结构化配置文件。

建议做法：

- 组合预算、线程池、数据库、超时这类框架参数继续放 `.env`
- 入场价、退出价这类交易阈值写 `current/config.py`
- 市场筛选词和 discovery 条件直接写 `current/market_filter.py`
- 订阅保留规则写 `current/subscription.py`
- 不要为了单一策略继续新增 `STRATEGY_CONFIG_PATH`

## 6. 开发交付最低要求

一个新的二次开发策略，至少要同时交付：

- `current/strategy.py`
- `current/config.py`
- `current/market_filter.py`
- `current/trading_strategy.py`
- `current/subscription.py`
- 契约测试通过
- replay 样例通过

## 7. 判断是否需要平台改造

只有出现下面这些情况，才值得动平台层：

- 现有 `StrategyContext` 拿不到必要状态
- 现有 `EntrySizing` / `StrategyDecision` 表达不了你的策略结果
- replay 和契约测试无法覆盖你的策略主语义

除此之外，优先把变化控制在 `strategies/current/`。
