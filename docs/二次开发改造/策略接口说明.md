# 策略接口说明

当前项目是单策略 runtime。

平台固定装配入口：

- `src/polymarket_trader/strategies/current/strategy.py`

`current/strategy.py` 当前就是实际运行的策略实现，也是后续二次开发入口。

## 必须实现的方法

一个策略模块至少需要提供：

- `build_discovery_queries() -> tuple[DiscoveryQuery, ...]`
- `select_market(market) -> UniverseDecision`
- `size_entry(context) -> EntrySizing`
- `decide_entry(context) -> StrategyDecision`
- `decide_exit(context) -> StrategyDecision`
- `decide_recovery(context) -> RecoveryDecision`

推荐同时导出：

- `build_strategy(config_path: str | None = None)`

平台会优先调用 `build_strategy`。如果没有，才会查找模块级 `strategy` 或 `STRATEGY`。

## 平台与策略的边界

平台负责：

- market 原始数据解析
- registry、账户快照、orderbook 快照收集
- Risk Manager、Order Executor、事件总线、worker 编排
- reconcile 执行动作提交

策略负责：

- 远端市场发现查询参数声明
- universe 选择
- entry sizing
- entry / exit 决策
- recovery 语义

结论很简单：

- 平台提供状态和执行边界
- 策略决定交易语义和市场发现条件

## `build_discovery_queries()`

平台会定时调用 `build_discovery_queries()`，再按返回结果访问官方 Gamma 发现接口。

- `endpoint` 选择 `events`、`events_keyset` 或 `markets`
- `params` 直接填写官方接口支持的查询参数，平台不做字段重命名和语义改写
- `max_pages` 控制单次扫描最多拉多少页
- `events_keyset` 必须使用 `after_cursor` 翻页，不能传 `offset`

官方参数文档：

- Events: <https://docs.polymarket.com/api-reference/events/list-events>
- Events Keyset: <https://docs.polymarket.com/api-reference/events/list-events-keyset-pagination>
- Markets: <https://docs.polymarket.com/api-reference/markets/list-markets>
- Markets Keyset: <https://docs.polymarket.com/api-reference/markets/list-markets-keyset-pagination>

中文约定：

- 远端发现负责把搜索范围收窄，减少无效扫描和速率浪费
- 最终是否进入策略 universe，仍然只能由 `select_market()` 判定
- 如果官方接口已经支持过滤，就优先把过滤条件写进 `params`

## WebSocket 订阅边界

`build_discovery_queries()` 返回的是 Gamma 发现接口参数，不是 WebSocket 订阅参数。

当前框架的边界如下：

- 策略负责：
  - 用 `build_discovery_queries()` 决定远端发现范围
  - 用 `select_market()` 决定 market 是否进入当前策略 universe
- 框架负责：
  - 根据当前 registry 中的 market 自动生成 WebSocket 订阅集合
  - 维护 `market_ws` / `user_ws` 的连接、重连、心跳和状态快照

当前实现里：

- `market_ws` 按 `NO token_id` 订阅 Market Channel
- `user_ws` 按 `condition_id` 订阅 User Channel
- 策略不会直接传 `assets_ids`、`markets`、`auth`、`type`

也就是说，策略对 WebSocket 订阅只有间接影响：

- 哪些 market 被发现并通过 `select_market()`
- 这些 market 进入 registry 后，框架再据此生成订阅参数

官方 WebSocket 文档：

- Overview: <https://docs.polymarket.com/market-data/websocket/overview>
- Market Channel: <https://docs.polymarket.com/market-data/websocket/market-channel>
- User Channel: <https://docs.polymarket.com/market-data/websocket/user-channel>

需要特别注意，官方 Market Channel 订阅消息只能控制两件事：

- `assets_ids`：订阅哪些 token
- `custom_feature_enabled`：是否开启 `best_bid_ask`、`new_market`、`market_resolved`

官方当前并不支持通过订阅参数按 `event_type` 精细筛选，例如：

- 不能只订 `price_change`
- 不能只订 `last_trade_price`
- 不能关闭 `book` 但保留 `price_change`

因此，Market Channel 的消息选择规则是：

- 订阅了某个 `assets_ids` 后，会收到该频道的默认消息类型
- 开启 `custom_feature_enabled: true` 后，再额外收到 custom feature 消息

当前项目里，`market_ws` 固定使用 `custom_feature_enabled: true`。

## `StrategyContext`

平台调用策略时会把热路径状态放进 `StrategyContext`：

- `market`
- `orderbook`
- `account_snapshot`
- `position`
- `open_orders`
- `now`
- `metadata`

当前约定里，`metadata` 里最重要的键有：

- `candidate_snapshots`
- `portfolio_budget_usdc`
- `available_usdc`
- `max_order_usdc`
- `max_market_usdc`
- `max_total_usdc`
- `entry_no_price_max`
- `min_liquidity_usdc`
- `max_spread`
- `allocation`
- `allocation_plan`
- `amount_usdc`
- `buy_budget_usdc`
- `size_shares`

## 返回值约定

### `UniverseDecision`

- `selected=True` 表示进入策略 universe
- `reason` 必须可读，便于事件审计和 replay 输出

### `EntrySizing`

- `allocation_plan` 是平台审计和回放使用的标准结构
- `allocation` 是当前目标 market 的预算结果
- `reason` 用于解释为什么分到这笔预算，或为什么没分到

### `StrategyDecision`

- `BUY` 需要给出 `price` 和 `amount_usdc`
- `SELL` 需要给出 `price` 和 `size_shares`
- `SKIP` 必须带 `reason`

### `RecoveryDecision`

当前恢复语义支持：

- `target_sell_size_shares`
- `cancel_order_ids`
- `replace_requests`
- `pause_market`
- `pause_reason`

## 配置加载

`build_strategy(config_path=...)` 可直接读取结构化配置。

当前内置加载器支持：

- `.json`
- `.toml`

入口工具：

- `polymarket_trader.strategy_api.load_strategy_config`
- `polymarket_trader.strategy_api.load_mapping_file`

- `pytest tests/strategies/contract`

- 在 Python 环境调用 `polymarket_trader.strategy_api.replay.run_entry_replay("tests/strategies/fixtures/entry_replay.json")`

如果你的策略改了输入字段、分配逻辑或返回语义，先把契约测试和 replay 修通，再去接 runtime。
