# docs 目录说明

该目录存放面向开发、运维、审计和人工管理的补充文档。这里的文档不替代 [需求文档](./需求文档.md) 与 [设计文档](./设计文档.md)，而是把当前实现需要反复遵守的接口、配置、操作和故障处置约束写清楚。

## 职责

- 说明 Admin API、配置项、运行流程和故障处置。
- 记录与部署、排障、审计、人工操作相关的工程约定。
- 把跨目录的架构边界写成可交接的规则，避免新增功能时破坏交易主链路。

## 文档索引

- [api.md](./api.md)：Admin API 的能力边界、禁止绕过项和输入输出约束。
- [config.md](./config.md)：配置分组、密钥约束、默认值和新增配置规则。
- [operations.md](./operations.md)：启动、停止、reconcile、人工操作和部署流程。
- [runbook.md](./runbook.md)：常见故障的处置顺序和优先级。
- [二次开发改造/改造计划.md](./二次开发改造/改造计划.md)：面向单策略可替换架构的二次开发改造方案。
- [二次开发改造/排产开发计划.md](./二次开发改造/排产开发计划.md)：面向多 agent 并行开发的任务切分、写入边界和合并顺序。

## 允许内容

- 面向人阅读的操作步骤、接口约定、配置解释和排障流程。
- 与业务规则相关但不适合写进代码注释的背景说明。
- 跨模块协作约定，例如谁能调用 Order Executor，谁能读取状态快照。

## 禁止内容

- 生产密钥、钱包私钥、API secret、数据库密码。
- 未脱敏的 raw response、签名 payload 或用户账户信息。
- 与当前架构相反的操作手册，例如直接通过 Admin API 绕过 Risk Manager 下买单。
- 已经废弃但未标注日期和替代方案的接口说明。

## 维护规则

- 新增外部接口、配置项、worker 或人工操作入口时，需要同步更新这里的对应文档。
- 涉及交易主链路的文档变更，需要明确是否新增外部调用、锁等待、队列或线程池依赖。
- 文档中的接口命名应与源码模块名保持一致，避免一套概念两套名字。
