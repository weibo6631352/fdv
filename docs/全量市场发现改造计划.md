# 全量市场发现改造计划

本文档定义曾经的 market discovery 全量轮扫改造方案。当前实现已重新开放扩展侧远端粗筛 hook：扩展通过 `ExtensionHooks.discovery_queries()` 提供查询片段，框架负责分页、限流、cursor 状态和结果进入统一 discovery worker。

这不是分阶段过渡方案。目标是一次切到目标形态，避免保留长期双路径、半接线和历史兼容分支，减少后续清理成本。

## 1. 改造目标

改造后 discovery 链路要满足以下目标：

1. discovery 主扫描面由扩展提供的远端粗筛 query 决定；未提供 query 时退回 active/closed 默认扫描。
2. 全量扫描采用连续轮扫模型：一轮扫到末页后，自动从头开始下一轮。
3. 热发现依赖 Market WebSocket 的 `new_market` 事件；Gamma 全量轮扫负责补漏和全覆盖。
4. 交易主链路优先级不变；全量扫描不能因为请求频率、解析负载或下游事件风暴反向影响 P0。
5. 代码只保留一套 discovery 主语义：扩展提供查询片段，框架统一分页和调度。

## 2. 范围定义

### 2.1 主扫描面

主扫描面定义为全量 active/open/clob_enabled 市场。

主 discovery 只关注“还有交易机会”的市场，因此默认排除：

- `closed=true`
- `archived=true`
- 已明确 resolved 且不可继续交易的市场
- orderbook 不可用或不接受订单的市场

### 2.2 非主扫描面

以下对象不进入主 discovery 全量轮扫：

- closed / archived 历史市场
- 已在运行时中进入终态、只剩审计价值的市场
- 仅用于报表、回测或历史统计的市场

这类对象如需刷新，走 reconcile 或离线任务，不和 discovery 主循环混在一起。

## 3. 一次性切换原则

本次改造按以下原则落地：

1. 不保留“旧 discovery 主路径 + 新轮扫主路径”长期并存。
2. 不把关键接线留到后续补丁，例如先上全量轮扫、后接 `new_market`。
3. 不引入只服务过渡期的配置项、状态字段或旁路逻辑。
4. 兼容层只允许保留在“定向实验扫描”这类非主路径用途，不能继续承担正式 discovery 主职责。

## 4. 目标形态

### 4.1 主 discovery 流

目标 discovery 调用链：

```text
ExtensionHooks.discovery_queries()
-> Gamma /markets/keyset
-> FullMarketScanCoordinator
-> MarketDiscoveryWorker
-> MarketService
-> ExtensionHooks.select_market()
-> MarketRegistry
-> MarketWsWorker
```

其中：

- `/markets/keyset` 负责稳定翻页；框架不每轮临时重建业务关键词，而是读取扩展提供的稳定 query 列表并维护 cursor。
- `FullMarketScanCoordinator` 负责维护 cursor、轮次和请求预算。
- `MarketDiscoveryWorker` 继续承担 raw payload 分类、事件发布和下游编排职责。
- extension 的 `discovery_queries()` hook 负责远端粗筛片段；框架覆盖 `limit` / `after_cursor` 并按 query 维护 cursor。
- extension 的 `select_market()` hook 继续负责本地 universe 精筛；是否可交易仍然由业务扩展决定。

### 4.2 热发现流

目标热发现调用链：

```text
Market WS new_market
-> MarketDiscoveryWorker.ingest_ws_new_market()
-> MarketService
-> Registry / tracker
```

这条链路负责把新市场尽快纳入运行时视野，减少全量轮扫的发现延迟。

### 4.3 状态维护流

已纳入 registry 的市场仍由以下链路维护：

- `market_resolved` / `best_bid_ask` / 其他 WS 生命周期事件
- reconcile 对 registry 内市场做权威刷新

主 discovery 不承担 closed/resolved 历史盘的维护责任。

## 5. 关键设计

### 5.1 使用 `/markets/keyset` 作为主入口

主 discovery 统一切到 Gamma `/markets/keyset`。

理由：

1. keyset 分页比 offset 更适合持续变化的 market 集合。
2. `next_cursor` 能明确表达是否到达末页，便于 round 边界判定。
3. 可以避免高频全量轮扫场景下的重页和漏页问题。

### 5.2 连续轮扫状态机

需要新增明确的扫描状态机，至少包含：

- `after_cursor`
- `round_id`
- `round_started_at`
- `last_round_completed_at`
- `last_page_size`
- `pages_scanned_in_round`
- `markets_seen_in_round`
- `last_error`

状态机规则：

1. 有 `next_cursor` 时继续当前 round。
2. 无 `next_cursor` 时结束当前 round，并清空 cursor。
3. 下一次调度从空 cursor 重新开始新 round。
4. 任何失败都不回退 registry 里已知市场，只记录失败并在下一次调度继续。

### 5.3 请求预算而不是 100ms 硬心跳

改造后不依赖“每 100ms 从头扫一次”的模式，而改成“每次调度消费固定请求预算”。

每次调度只允许处理：

- 固定页数，或
- 固定 request budget，或
- 固定最大运行时长

这样可以保证：

- round 会持续推进；
- discovery 不会常驻占满 event loop；
- 上游限速和下游事件量都可控。

### 5.4 去重与幂等

全量轮扫天然会重复读到同一个市场，因此 discovery 链路必须显式幂等。

最少要做：

- 以 `condition_id` 为主键、`market_slug` 为辅键的 market 去重
- 相同 market 在短时间内的重复扫描合并
- round 切换时避免把同一 market 当成“新市场”重复放大为大量维护事件

要求是“重复读到同一个 market”只能更新必要元数据，不能制造无意义事件风暴。

### 5.5 WS 热发现必须同时接通

本次改造要求把 `new_market -> MarketDiscoveryWorker` 一并接好，不接受“后面再补”。

原因：

- 全量轮扫只保证最终覆盖；
- `new_market` 才能提供低延迟发现；
- 两者同时在位，才能兼顾广度和时效。

## 6. 代码改动清单

### 6.1 `polymarket_trader.extension_api`

当前 discovery 契约已调整为：

处理原则：

- `discovery_queries()` 提供远端粗筛 query；
- `select_market()` 继续负责本地 universe 精筛；
- 框架负责分页、限流、cursor、失败重试和事件合并入口。

### 6.2 `main.py`

需要重构以下部分：

1. scheduler 不再每轮临时重建 query 并丢失 cursor。
2. 新增连续轮扫 runner。
3. 调度周期改为驱动扫描预算消费，而不是驱动一次完整 discovery 轮次。
4. 扫描状态要在 runtime 中可见，便于 supervisor / admin 查询。

### 6.3 `infra/polymarket/gamma_client.py`

需要补充 `/markets/keyset` 支持，并统一 DTO 适配。

要求：

- 与现有 `events/keyset` 风格一致；
- 暴露 `next_cursor`；
- 保持参数归一化、异常类型和 timeout 语义一致。

### 6.4 `workers/market_discovery_worker.py`

需要保留现有分类与事件编排职责，并补强：

- 按 condition_id / slug 的幂等控制
- 来自轮扫与来自 WS 的统一入口
- round / source 维度的指标与审计字段

### 6.5 `workers/market_ws_worker.py`

需要把 `new_market` 消息真正导向 discovery worker，而不是只做 metadata 更新。

要求：

- 不绕过同一套 classifier / universe 规则
- 不在 WS worker 里复制 discovery 业务判断
- 不影响现有盘口快照和 resolved 处理链路

### 6.6 `runtime` / `observability`

需要新增 discovery 可观测性，至少包括：

- 当前 round id
- 当前 cursor 是否为空
- 上一轮完成时间
- 当前 round 已扫描页数
- 当前 round 已看到市场数
- discovery 重复率
- 本轮发现数 / 更新数 / 过滤数
- 连续失败次数

## 7. 配置项

本次改造后，discovery 侧至少需要以下框架配置：

- `market_discovery_page_limit`
- `market_discovery_request_budget_per_tick`
- `market_discovery_tick_seconds`
- `market_discovery_max_runtime_ms`
- `market_discovery_retry_backoff_seconds`

策略配置中的关键词列表可通过扩展 hook 转成远端 query，但分页、限流和 cursor 状态仍归框架所有。

## 8. 测试要求

本次改造必须一次把测试补齐，不能只补 happy path。

至少覆盖：

1. `/markets/keyset` 翻页成功
2. 无 `next_cursor` 时 round 正确结束
3. 新 round 能从头重新开始
4. 同一 market 多次扫到时不会重复制造错误事件
5. `new_market` 能进入 discovery worker
6. discovery 失败后不清空已有 known markets / registry 热态
7. 调度预算用尽时，扫描状态能在下一次继续推进
8. extension query 的 cursor、完成状态和请求预算由框架维护

## 9. 验收标准

改造完成后，以以下条件作为验收标准：

1. runtime 能按 extension query 持续分页扫描；未提供 query 时能退回默认 active 市场扫描。
2. 任意时刻都能从运行时观测到当前 round 和游标推进状态。
3. 新 market 可以通过 WS 热发现快速进入 discovery 流。
4. 主 discovery 不扫描 closed/resolved/archived 历史盘。
5. 多轮全量扫描不会造成显著重复事件风暴。
6. 交易主链路指标在开启全量扫描后仍保持在现有告警阈值内。
7. 代码中不存在长期保留的旧主 discovery 路径。

## 10. 不做的事

本次改造明确不包含：

- 把 closed/resolved/archived 历史市场放回主 discovery 全量轮扫
- 为过渡期保留长期双 discovery 主路径
- 用 100ms 固定周期从第一页反复重扫
- 把策略 universe 判断下沉到 WS 或 infra 层绕过 `MarketService`

## 11. 实施顺序

虽然本次要求一次性切换，但提交内容内部仍应按以下顺序收口，保证最终结果干净：

1. 先补 `/markets/keyset` 客户端与 DTO。
2. 再引入连续轮扫状态机与 scheduler runner。
3. 同一个提交集内完成 `new_market` 接线。
4. 同一个提交集内删除 discovery 主路径对策略 query 的依赖。
5. 最后统一补测试、文档和可观测性。

这里的“顺序”是代码内部收口顺序，不是对外分阶段上线方案。
