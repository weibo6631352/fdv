# 04 文档与注释规范任务

## 覆盖范围

- 设计文档 `5.1 编码与文件格式`
- 设计文档 `5.2 中文注释规范`
- 设计文档 `5.3 并发与性能开发规范`
- 设计文档 `5.4 代码审查与测试规范`

## Worker 任务

- 维护 README、docs、目录 README 与计划文档的一致性。
- 确保源码、配置示例、Markdown 文档、迁移脚本和测试文件使用 UTF-8 编码，推荐无 BOM；仓库统一 LF 换行。
- 业务变量和代码标识建议使用英文；用户可见文案、业务规则说明和注释使用规范中文。
- 注释需要覆盖核心交易规则、风控原因、并发边界、锁使用原因、外部 API 适配差异、异常降级策略和难以从代码直接看出的业务约束。
- 注释应解释“为什么这样做”和“违反后会发生什么”，避免重复描述代码本身。
- 新增 worker、队列、锁、线程池、进程池或外部调用时，文档必须说明所属优先级和 P0 影响。
- PR / 提交说明需要标注是否影响 P0 交易链路，以及是否新增锁、队列、线程池或外部调用。

## 交付物

- 文档同步检查清单。
- 注释规范检查清单。
- P0 影响说明模板。

## 并行接口

- 上游：所有项目组。
- 下游：代码审查、验收测试计划、runbook。
- 与根 README 的开发阶段规则保持一致。

## 注释要求

本任务定义注释规范本身；所有新增注释应解释业务原因、并发边界和异常后果。开发阶段不要求补充或运行验证测试。
